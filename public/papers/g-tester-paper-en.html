Abstract

Traditional Software Quality Assurance (QA) relies heavily on manual engineering effort, causing operational friction, extended delivery cycles, and inconsistent assessment criteria. While autonomous artificial intelligence agents offer high-throughput code and runtime evaluation, pure generative approaches often suffer from parametric hallucination, non-reproducibility, and a lack of deterministic validation.

This paper presents G-Tester, an enterprise-grade Quality Assurance as a Service (QAaaS) architecture developed by ALFACAN DEFENCE GROUP LIMITED. G-Tester unifies a horizontally scalable test-runner fleet with an interactive multi-agent council of specialized Large Language Models (LLMs). The platform incorporates a real-time AI Boardroom Interface, allowing human operators and lead auditors to visually monitor live multi-model debates, step into agent channels, adjust testing parameters dynamically, or override verdicts. Every analytical decision is anchored by a two-stage Retrieval-Augmented Generation (s-rag) engine over a curated house doctrine corpus, enforcing multi-tier invariants: Honesty (explicitly reporting unexecuted paths as skips rather than passes), Grounding (restricting reasoning to executed telemetry and doctrine rules), and Graceful Degradation (falling back to deterministic execution rules when inference infrastructure is unavailable).

1. Introduction & Architectural Motivation

1.1 Structural Bottlenecks in Modern Software QA

Modern microservice architectures and high-velocity continuous integration/continuous deployment (CI/CD) pipelines strain traditional QA paradigms. Industrial testing faces four primary bottlenecks:

  • Temporal Latency and Resource Costs: Comprehensive end-to-end, security, and performance testing requires days or weeks of dedicated senior engineering time per major release.
  • Subjective and Non-Reproducible Assessment: Severity scoring and flaw prioritization vary across human engineers, leading to subjective triage outcomes.
  • Toolchain Fragmentation: Disparate tools (load generators, static analyzers, DAST probes, accessibility drivers) emit isolated data streams, requiring labor-intensive manual consolidation.
  • The "Black-Box" Automation Problem: Automated testing scripts run silently without providing real-time visibility into why specific decisions, coverage skips, or risk severity ratings were assigned.

1.2 The Human-in-the-Loop Multi-Agent Council Solution

G-Tester resolves these structural issues by pairing automated execution runners with a transparent Multi-Agent AI Council. Instead of executing analysis in an opaque background thread, G-Tester surfaces the live multi-model deliberation process directly to the user through an interactive dashboard. Human auditors can observe domain analysts debating exploitability in real time, inspect retrieved doctrine rules, pause execution, or interject custom parameters before final package compilation.

2. Interactive Live AI Boardroom & Human-in-the-Loop Governance

A central feature of G-Tester is its real-time multi-agent visualization interface, termed the AI Boardroom. When an audit job is initiated, the platform spawns a collaborative session where specialized AI agents deliberate over live runner telemetry.

2.1 Real-Time Telemetry and Event Streaming

The G-Tester control plane streams structured events via WebSockets and Server-Sent Events (SSE) to the client dashboard. As runners yield execution metrics (e.g., HTTP headers, stack traces, DOM snapshots, p95 latency numbers), the AI analysts process the data in parallel channels.

2.2 Human Intervention Mechanics

G-Tester provides three modes of human control during an audit:

  1. Active Intervention (Mid-Run Steering): A human lead can pause the council's deliberation and type instructions into the live stream (e.g., "Re-evaluate the SQL injection finding assuming an upstream WAF is present"). The agents immediately acknowledge the override and adjust analysis.
  2. Discipline Scope Modification: If an agent detects anomalous behavior, it suggests spawning an additional runner (e.g., nonfunc_load). The client receives a visual prompt to approve or decline on the fly.
  3. Verdict & Severity Overrides: Before final signing, human auditors can review findings, adjust severity ratings, or append notes. All overrides are cryptographically logged in the final audit package.

5. Grounding, Deterministic Verdicts, and Self-Learning Loop

5.1 Two-Stage Retrieval-Augmented Generation (s-rag)

To eliminate model hallucination, analyst reasoning is bound to a curated house doctrine corpus using a two-stage retrieval pipeline:

  1. Stage 1 (Vector Recall): High-dimensional vector search using Qwen3-VL-Embedding-8B (1024-dimensional embeddings) identifies relevant doctrine entries based on domain query context.
  2. Stage 2 (Cross-Encoder Precision): Candidate passages are re-scored by Qwen3-Reranker-0.6B, ensuring that only the most relevant operational rules are injected into the context window.

5.2 Deterministic Release Verdict

6. Scale Infrastructure & Empirical Validation

G-Tester decouples API control tasks from test execution workloads. A lightweight control server handles job intake, billing, and real-time streaming, while a distributed, autoscaling worker fleet (gt-runner) executes heavy runner processes. Workers claim pending jobs using lock-free atomic queries (SELECT ... FOR UPDATE SKIP LOCKED), supporting horizontal scaling across large server clusters.

7. Conclusion

G-Tester establishes a collaborative, evidence-grounded framework for autonomous software testing. By pairing a multi-model council of specialized LLM analysts with an interactive live dashboard, the system bridges automated machine-scale execution with transparent human-in-the-loop oversight.
